# استخراج حقول الفواتير باستخدام LightOnOCR

مراجعة المصادر: 4 أكتوبر 2026. توصية تصميم، وليست نتائج اختبار على ملفات المشروع.

تحديث النطاق بعد توضيح المستخدم: نحو 160 قالبًا يصف تنوع المدخلات فقط. المنتج مطلوب منه استخراج حقول موحدة من المحتوى؛ التعرف على القالب ليس متطلبًا. المقترحات الخاصة بمطابقة القوالب أدناه بدائل لتحسين التكلفة عند الحاجة، وليست خطوة لازمة في المسار. الاتجاه الحالي بدء الاستخراج العام باستخدام النموذج المحلي المتاح، ثم تحسين التكلفة وفق قياسات الدقة والأداء. توثيق المصطلحات في [CONTEXT.md](../CONTEXT.md).

## المتطلبات المؤكدة

صور أو PDF، عربي وإنجليزي، نحو 160 شكلًا متكررًا. الحقول: رقم الفاتورة، اسم المورد، التاريخ، الإجمالي، مبلغ الضريبة، العملة. اختار المستخدم LightOnOCR بدل Docling. الحجم الشهري غير محدد.

هذه العملية استخراج حقول؛ تحديد نوع الوثيقة أو قالبها تصنيف مستقل يمكن استخدامه لتوجيه الاستخراج.

## الحقائق الموثقة

- LightOnOCR-2-1B نموذج رؤية ولغة بحجم مليار معامل يحول صفحات المستندات إلى نص مرتب. المثال الرسمي يحول PDF إلى صور صفحات. القراءة ليست ضمانًا لاستخراج حقول أعمال صحيحة. [بطاقة النموذج](https://huggingface.co/lightonai/LightOnOCR-2-1B).
- نسخة bbox تحدد مواقع الصور المضمنة. لا تعتبرها مصدرًا مضمونًا لإحداثيات الكلمات أو الحقول؛ تظليل الحقول يحتاج آلية إضافية لتحديد النص. [بطاقة bbox](https://huggingface.co/lightonai/LightOnOCR-2-1B-bbox).
- بطاقة الإصدار الأول تذكر غلبة النصوص بالحروف اللاتينية في التدريب. نتائج الاختبارات العامة لا تثبت دقة الفواتير العربية؛ اختبر النسخة المختارة على ملفات المشروع العربية والمختلطة. [بطاقة الإصدار الأول](https://huggingface.co/lightonai/LightOnOCR-1B-1025).
- TF-IDF مع مصنف خطي خيار موثق لتصنيف النصوص. اختباره لتحديد القوالب اقتراح هندسي، وليس دقة مثبتة لهذه الفواتير. [مثال scikit-learn](https://scikit-learn.org/stable/auto_examples/text/plot_document_classification_20newsgroups.html).

## البنية المقترحة

1. حفظ الأصل والنص الخام بحسب الصفحة وإصدار النموذج والإعدادات.
2. schema موحدة للحقول الستة. إجمالي الفاتورة مختلف عن المبلغ المستحق، ومبلغ الضريبة مختلف عن نسبتها. رقم الفاتورة يبقى نصًا لحماية الأصفار والأحرف؛ الحقول الغائبة أو الملتبسة لا تخمن.
3. قواعد استخراج عامة تعتمد العناوين العربية والإنجليزية وسياق النص، مع تطبيع الأرقام والفواصل والتواريخ. قواعد الإحداثيات تحتاج مصدرًا إضافيًا للمواقع، ولا تفترض توفرها من LightOnOCR.
4. للقوالب كثيرة الاستخدام: تحديد المورد ونسخة القالب من البيانات الثابتة والعناوين؛ عند الحاجة اختبار TF-IDF مع LogisticRegression أو LinearSVC. السماح بنتيجة «قالب غير معروف». أعلى درجة ليست ضمانًا، وLinearSVC لا يعطي احتمالًا معايرًا تلقائيًا. [مرجع المعايرة](https://scikit-learn.org/stable/modules/calibration.html).
5. إعدادات قوالب مشتركة قابلة للإصدار بدل برامج منفصلة. المورد الواحد قد يملك عدة قوالب.
6. LLM نصي لاستخراج الحقول الناقصة أو الملتبسة إلى JSON، مع الصفحة ومقطع النص الداعمين. صحة JSON لا تثبت صحة القيم. إذا أخطأ OCR في الرقم، فالبديل إعادة قراءة الصورة أو نموذج بصري أو مراجعة بشرية.
7. التحقق من الحقول المطلوبة وصيغ القيم وتناسق المبالغ عند توفر بيانات كافية، مع مراعاة الخصومات والرسوم والتقريب. نجاح الحساب وحده لا يثبت المورد أو التاريخ.
8. شاشة تعرض الأصل والقيم والحالات التي تحتاج مراجعة، ثم التصدير حسب احتياج المنتج.

## البداية والتكلفة

لا تبنِ 160 قالبًا قبل التجربة. قارن على عينات متنوعة: LightOnOCR مع قواعد، ومع LLM للحقول الستة، ومع قواعد وLLM للحالات الاستثنائية.

يمكن بدء نموذج أولي بـ LLM لاستخراج الحقول، ثم إضافة قواعد للقوالب الأكثر استخدامًا لتقليل العمل المتكرر. هذا يقلل جهد إعداد كل القوالب مبكرًا، ولا يضمن أن LLM هو الأرخص إجمالًا.

احتفظ باختبار مستقل لم يستخدم لبناء القواعد أو ضبط الحدود؛ امنع تسرب نسخ الفاتورة وصفحاتها بين التطوير والاختبار، واختبر القوالب غير المعروفة منفصلة. [مرجع الفصل بين التدريب والتحقق والاختبار](https://scikit-learn.org/stable/modules/cross_validation.html).

قِس صحة كل حقل، وصحة الحقول الستة معًا، ونسبة المرور الآلي الصحيح وأخطاء القبول الآلي، ونسبة استخدام LLM والمراجعة البشرية، وزمن المعالجة. افصل النتائج حسب اللغة والقالب وجودة الملف.

التكلفة تشمل تشغيل LightOnOCR، واستخراج LLM، والمراجعة، وبناء وصيانة القواعد. التشغيل المحلي له تكلفة حتى دون API. يلزم الحجم الشهري وعدد الصفحات والعتاد ونسبة الحالات الاستثنائية لتقدير السعر. النظام الهجين هو المرشح الأول؛ التجربة تحسم مقدار الاعتماد على القواعد والنماذج.
